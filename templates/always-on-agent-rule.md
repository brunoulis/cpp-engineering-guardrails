# Lightweight always-on rule (for AGENTS.md / CLAUDE.md / Hermes project instructions)

For C++ tasks use `cpp-engineering-guardrails` when available. Inspect build system, C++ standard, affected public contracts and existing local modifications before edits. Choose **AUDIT**, **IMPLEMENT**, **REFACTOR** or **DEEP-REFACTOR** based on the request. Ownership/lifetime, API/ABI, error semantics, thread lifetime and tests are strong rails; patterns, target layout, file count and performance strategies are conditional decisions. Keep changes scoped; compare a minimal fix, structural alternative and leave-as-is. Don't assert that checks ran unless they did. Report PASS/FAIL/UNVERIFIED, precise commands and reviewer status. Never rewrite tests or suppress diagnostics to create green CI. Load only the relevant skill reference files.
